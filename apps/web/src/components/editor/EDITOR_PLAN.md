# DEditor 演进计划（对标 Office Word / Google Docs）

## 1. 目标与范围

### 目标
将当前 `DEditor` 从基础富文本编辑器，演进为可用于生产的“文档编辑核心”，体验接近 Word/Google Docs：
- 更完整的排版能力
- 稳定的编辑性能
- 可扩展的工具栏与命令体系
- 可持续迭代（便于后续协作、评论、版本等高级功能）

### 当前范围（本阶段）
先聚焦“单人编辑”能力，不直接实现多人实时协作。

**Phase A 验收标准**：
- ✅ 90% 常用文档编辑动作可通过按钮完成

- ✅ 所有工具在工具栏中可见且功能正常

**Phase A 已实现功能清单**：
- 文本格式：加粗、斜体、下划线、删除线、高亮、文本颜色（主色/默认）、行内代码
- 标题级别：H1、H2、H3、H4、正文
- 段落对齐：左对齐、居中、右对齐、两端对齐
- 列表：无序列表、有序列表、任务列表
- 块级元素：引用块、代码块、分割线、表格
- 表格操作：插入表格 (设定行列数)、在后/前插入行、删除行、在后/前插入列、删除列、删除表格
- 内容插入：链接(URL 输入框)、图片(URL 输入框)
- 编辑工具：清除格式、撤销、重做
- **Slash 命令菜单**：输入 "/" 快速插入块级元素（标题、列表、表格、代码块、引用、分割线、图片、链接）
- **共 34 个工具按钮**，组织为 4 组：style(8) | heading(9) | block(14) | action(3)
- **菜单支持**：Slash 菜单 13 个快捷命令，支持↑↓箭头导航、Enter 确认、Escape 关闭、模糊搜索

## 3. 推荐目录落地（编辑器组件根目录）

建议在当前目录逐步补齐：

- `DEditor.vue`：主编辑容器
- `DEditorToolbar.vue`：工具栏 UI
- `types.ts`：共享类型
- `commands/`：命令封装（按功能分）
- `extensions/`：TipTap 扩展定义
- `toolbar/`：工具栏配置与分组定义
- `services/`：序列化、导出、草稿存储
- `__tests__/`：编辑器单测与交互测试
- `EDITOR_PLAN.md`：本计划文档

---

## 4. 落地顺序（建议）

1. 先做 `toolbar` 配置中心化（按钮定义、权限、快捷键）
2. 再做 `commands` 抽象（run/can/isActive 统一）
3. 接着补 `extensions`（任务列表、表格、对齐、颜色）
4. 然后做 `services`（自动保存、导入导出）
5. 最后补测试与性能优化

---

## 5. 风险与应对

- 风险：功能扩展后 toolbar 与命令耦合严重
  - 应对：配置驱动 + 命令层统一接口
- 风险：大文档性能下降
  - 应对：减少响应式计算、按需更新工具栏状态
- 风险：导入导出格式不一致
  - 应对：定义统一文档 schema 与双向转换测试
